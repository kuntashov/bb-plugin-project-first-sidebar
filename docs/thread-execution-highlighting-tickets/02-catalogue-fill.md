# 02 — Заполнить индекс всех видимых тредов в фоне

**Что сделать:** после запуска плагина автоматически показать подтверждённые результаты по всему каталогу, включая архив, не ожидая открытия окна или включения опции. [Спецификация](../thread-execution-highlighting-spec.md): Catalogue, jobs and concurrency; Errors, recovery and lifecycle.

**Блокируется:** 01 — Показать последнюю принятую конфигурацию одного треда.

**Статус:** ready-for-agent после устранения блокировок и сверки спецификации.

- [ ] Миграция storage плагина предшествует сервису; запуск фабрики и обычного списка не ждёт заполнения. Полный `threads.list({includeHidden:false})` без limit/offset/archive-фильтра формирует сохранённый manifest активных и архивных видимых неудалённых ID; контракт и размер ответа проверены на поддерживаемом SDK.
- [ ] Одна серверная задача с ограниченным числом workers (начальная цель — четыре) обрабатывает активные раньше архивных, не более одной операции чтения/записи на ID. Подтверждённые результаты initial становятся доступны по мере готовности; несколько окон не запускают дополнительные полные заполнения.
- [ ] Для каждого ID сохраняются pending/done/error и результат с транзакционным checkpoint независимо от порядка завершения. Ошибки видны на уровне списка/настроек без toast на каждую строку; ошибка не маскируется отсутствием данных.
- [ ] Тесты демонстрируют полный архив независимо от UI, ограничение параллелизма, порядок завершения, частичный результат и сохранение корректности при ошибке транзакции. Зафиксировать фактическое runtime-подтверждение отдельно от тестового стенда.
