# 07 — Подтвердить полную приёмку и документировать поведение

**Что сделать:** собрать доказательства полной работы подсветки, включая реальные SDK и UI, и обновить пользовательскую документацию. [Спецификация](../thread-execution-highlighting-spec.md): Testing decisions, Out of scope и Technical verification questions.

**Блокируется:** 06 — Сохранить взаимодействия и доступность подсвеченной строки.

**Статус:** ready-for-agent после устранения блокировок и сверки спецификации.

- [ ] Сверить все критерии спецификации с результатами 01–06; закрыть обнаруженные дефекты в согласованном объёме и повторно проверить затронутые сценарии. Отдельно перечислить подтверждённые и непроверенные случаи.
- [ ] В подходящем изолированном runtime измерить холодный и тёплый SDK-путь, размер ответов и фоновую активность; проверить поддерживаемый диапазон BB/SDK, каталог, payload и sequence boundaries, edit/clear/fork и корреляцию встроенных provider paths. Прямые SQL-замеры и синтетические тесты не выдавать за runtime evidence.
- [ ] Проверить обе темы и доступность, взаимодействия и два окна; задокументировать настройку, смысл последнего accepted, ошибки, пересборку и ограничение 413 без обещания атомарного snapshot двух БД.
- [ ] Выполнить соответствующие тесты, `npm test` и `npm run typecheck`; сборку `npm run build` выполнить только в GitHub Actions при отдельно доступной авторизации и зафиксировать её результат. При недоступности runtime или Actions оставить приёмку соответствующей части открытой, указав причину.
