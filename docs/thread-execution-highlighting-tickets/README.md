# Локальные задачи: подсветка выполнения тредов

Источник требований — [спецификация](../thread-execution-highlighting-spec.md). Каждая задача даёт проверяемый сквозной результат и включает собственные тесты. До назначения исполнителей интегратор сверяет задачи с окончательной редакцией спецификации после независимого challenge; при расхождении обновляет задачи. Уточнения, полученные от владельца: fork отображается после успешного фонового чтения без нового запуска; кнопка присоединяется к initial/rebuild и недоступна во время recovery; проверяются неизменный accepted и изменение истории при той же identity.

Порядок интеграции: 01 → 02 → 03 → 04 → 05 → 06 → 07. Зависимости блокируют начало следующей задачи до интеграции результата предыдущей: срезы последовательно расширяют общую серверную проекцию и клиентский контракт. 07 завершает сквозную приёмку всех срезов. Каждая задача остаётся проверяемой сама по себе; промежуточное поведение ограничено её описанным объёмом и не объявляется полной реализацией.

Общие рамки: сохранять публичную чистоту материалов и истории; использовать только публичный SDK и SQLite плагина, без чтения БД BB, изменения ядра, обходных схем и хранения текста сообщений. Тесты и typecheck допустимы локально, сборка плагина — только в GitHub Actions. Установка, deploy, release, marketplace и merge не входят в задачи. Реальные runtime/визуальные проверки и синтетические тесты учитывать раздельно; недоступную проверку обозначать как непроверенную. Не повторять гриллинг пользователя по согласованным решениям. При техническом препятствии сообщить интегратору, не подменять требования.
