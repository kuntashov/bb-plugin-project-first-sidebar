# 05 — Возобновлять работу и устранять пропущенные изменения

**Что сделать:** после прерывания или разрыва соединения индекс возвращается к истории BB, а непроверенные и ошибочные результаты не выглядят актуальными. [Спецификация](../thread-execution-highlighting-spec.md): Errors, recovery and lifecycle; Catalogue, jobs and concurrency.

**Блокируется:** 04 — Пересобрать индекс без потери рабочего поколения.

**Статус:** ready-for-agent после устранения блокировок и сверки спецификации.

- [ ] При старте сохранённые данные unverified до сверки; незавершённая job возобновляется с per-ID checkpoint, ранее done ID тоже проверяются. После штатного рестарта без незавершённой job идёт фоновая проверка каталога и accepted всех ID без отдельной параллельной recovery job. После reconnect/resume сверяются полный каталог и история, включая offline additions/deletions; окна перечитывают проекции.
- [ ] Targeted transient ошибки SDK/network/SQLite busy повторяются максимум три раза через 1/5/15 секунд; состояние ошибки и незавершённая работа сохраняются. После exhaustion нужен event, rebuild или restart; 413, malformed и несопоставимая пара терминальны для автоповтора. Классификацию проверить по реальным формам ошибок.
- [ ] Ошибка live writer снимает недостоверный цвет соответствующего ID; building-only ошибка сохраняет подтверждённую working проекцию. Dispose отменяет подписки, таймеры и очередь, инвалидирует токены до закрытия SQLite; поздний callback не пишет в закрытую БД.
- [ ] Детерминированные тесты покрывают restart до/после commit, пропущенный accepted, reconnect и два окна, retry timing/exhaustion/new trigger, terminal errors и dispose с ожидающими операциями. Где возможно, подтвердить семантику транзакций и lifecycle в изолированном runtime.
