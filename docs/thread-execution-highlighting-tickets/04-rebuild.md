# 04 — Пересобрать индекс без потери рабочего поколения

**Что сделать:** пользователь запускает пересборку в настройках, видит прогресс и результат, пока подтверждённая рабочая проекция продолжает обновляться. [Спецификация](../thread-execution-highlighting-spec.md): Catalogue, jobs and concurrency; Client contract.

**Блокируется:** 03 — Обновлять индекс при изменениях истории и каталога.

**Статус:** ready-for-agent после устранения блокировок и сверки спецификации.

- [ ] Кнопка и RPC показывают состояние, processed/discovered, ошибки и итог; счётчики могут изменяться при изменении каталога. Запросы из нескольких окон присоединяются к одному initial или rebuild; во время recovery кнопка недоступна и объясняет, что нужно дождаться завершения recovery; после этого можно начать полную пересборку. Нет параллельных полных задач.
- [ ] Rebuild пишет отдельное building поколение; working поколение доступно и live. Один последовательный writer на ID координирует поколения, актуальные результаты и checkpoint записываются атомарно; ошибка только building не уничтожает подтверждённые рабочие данные.
- [ ] Cutover возможен лишь при done и ready/absent для всех ID, отсутствии ошибок, pending, dirty membership/live работы и незавершённых записей. Pointer и успех job меняются одной синхронной транзакцией, старые результаты ограждены, затем отправляется одна invalidation и очищаются только старые поколения индекса плагина.
- [ ] Тесты покрывают два окна и все виды работающей задачи, ошибку/413 без cutover, live и membership во время rebuild, barrier и поздний результат, сбой до и после pointer commit и cleanup. Атомарность между БД BB и плагина не заявляется.
