# 01 — Показать последнюю принятую конфигурацию одного треда

**Что сделать:** провести один тред от чтения его сохранённой истории через проекцию и пакетный RPC до доступного пояснения в строке. Это первый ограниченный сквозной срез; автоматический полный каталог и live-обновление добавляются следующими задачами. Контракт и ограничения: [спецификация](../thread-execution-highlighting-spec.md), разделы Solution, Boundaries and extraction, Client contract и Testing decisions.

**Блокируется:** нет; до изменения поведения сверить актуальную редакцию спецификации после challenge.

**Статус:** ready-for-agent после сверки спецификации.

- [ ] В настройках Organize → Rows рядом с Provider icons есть одна синхронизируемая опция, по умолчанию выключенная. Для запрошенного треда результат доступен через валидируемый batch RPC; в строке изменяется только название, полное название и пояснение доступны.
- [ ] Последний `turn/input/accepted` сопоставлен по request ID с предшествующим `client/turn/requested`: начать с limit 1, при необходимости идти назад страницами до 100, включая несмежные события. Нет accepted — absent; некорректная пара или 413 — error. Проверить фактические формы SDK и границы последовательностей.
- [ ] Красный для High+ и fast, оранжевый для High+, фиолетовый для fast, обычный иначе; High+ только high/xhigh/ultracode/max/ultra, fast только fast. Неизвестные измерения независимы; loading, unverified и error не выдаются за актуальный цвет или absent.
- [ ] Сохраняются только нормализованная пара и происхождение, без текста или полной копии событий; queued, rejected и draft не меняют результат. Тесты покрывают матрицу, страницы, отсутствие, malformed, 413 и доступность. История читается сервером, не при каждом рендере строки.
